# 运维开发与验证

运维包含代码、脚本和配置开发；执行环境与授权边界由 Ops 核实，规模沿用用户确认的约定，均由 Ops 交接。先读项目入口、相关实现/测试与 runbook，采用已有源码和发布方式，不另建通用框架。仓库编辑、隔离测试、发布及线上验收是不同步骤，前一步成功不授权后一步。

## 实现与隔离验证

- 以原始需求和规模约定限定实现与验证，不把本节当作每个脚本必须实现的功能清单。极小固定用途脚本优先直接流程；只检查实际存在的输入、状态和风险，不为了满足检查项新增 CLI 模式、配置体系、持久状态、恢复系统、部署生成器或内置测试框架。确需超出约定时交回 Ops 处理，不自行扩大范围。
- 先确定目标状态、输入、失败条件和验证入口。重复工作才写脚本；帮助、目标参数和 dry-run 按项目要求及实际使用需要提供，不为固定目标发明可配置接口。保留安全默认值，不默认执行主机变更；代理执行前的授权确认不自动等于脚本必须内置执行开关。项目已有明确要求仍须遵守，冲突交回 Ops 说明，不擅自删除。dry-run 是否写锁、临时文件或通知须查实现，名称不证明只读。
- 对实际接受的输入校验类型、范围、必填项、路径归属与解析后的边界，拒绝控制字符、选项注入和未知选项。外部输入逐项传参并正确引用；配置按数据解析，不 `source`、`eval` 或拼成命令，不读取凭证正文来测试解析。
- 测试用明显占位值及独立临时目录，排除真实数据、受保护挂载、生产通知和网络目标；把所有可写路径、锁、状态及外部命令替换为受控 fixtures/fakes。先检查覆盖完整，不能因替换一个命令就假定已隔离；只清理本次拥有且已无执行者使用的对象。
- 按项目工具链运行语法、静态检查及聚焦测试，覆盖实际的有效/无效输入、依赖失败、空结果及必要的中断后行为；不为测试中断而先建立恢复系统。优先验证日常使用能否完成、单次失败是否妨碍后续运行及无关资源是否受影响，不只验证代理新增的机制。测试可在独立临时验证中完成，不因单文件交付就把测试框架塞进运行脚本。Shell 管道、子进程与通知失败须按语义传播，不能被后续成功输出掩盖；清理失败保留可辨认现场，不以忽略退出码制造通过。
- 原生配置检查只验证配置，不启动服务；避免输出展开后的敏感值。隔离环境缺少目标依赖时明确标注限制，不据此断言线上配置失败，也不为补验证自动安装或连接目标。

## 发布与验收

- 发布前重新核对获准目标、执行身份、源/目标路径、传输路线、版本或摘要、依赖、权限、备份和恢复限制；客户端路径不能直接充当远端安装源。不为普通用户运行而放宽上层私有目录权限。
- 启动、重载、调度或恢复可能触发真实写入；列入发布范围与 Ops 风险确认，不以静态检查、历史批准或“只是重启”替代。异常时核对原任务，不重复启动状态未知的操作；长任务另读 [长任务协议](long-tasks.md)。
- 发布后独立检查实际版本、运行配置、状态、可达性及有界日志，再按原始目标核验用户可见行为和合理观察窗口。调度已启用不等于任务自然完成；备份存在不等于已验证恢复，命令退出零不等于业务通过。
- 同步项目既有文档与记录，分别标明已实现、仓库验证、已发布、业务验收及未覆盖项；记录预期、实际与结果。生产证据缺失时保持未验证，不为补齐结论制造破坏性故障或自动发布。
