# Ops 工作区、留痕与 Git

仅在规划初始化、持久化记录或提交时读取。遵循已有 `AGENTS.md`、目录与授权，缺少资料不阻塞安全只读调查。

## 初始化与接续

- Local 在当前运维仓库，不使用远端 `~/ai-ops`；Remote 在已确认目标的 `~/ai-ops`。选择 Ops、连接、未登记 Host 或缺少目录都不授权初始化。仅在用户要求或当前任务确需持久化资料时提出方案；同意规划不等于同意写入，Remote 仍走 Low / High。
- 写入前检查目录归属、Git 状态、相关未完成记录与目标路径，已有同名无关目录不覆盖。没有入口时继续独立于目录的安全调查，确需写入才请求决定。不得擅自登记 Host 清单。
- 初始化保持最小：入口 `AGENTS.md`、简短 `README.md`、批准范围的主机说明与服务索引、操作记录与测试所需结构，不预建空模板。无既有约定时推荐 `operations/LOG.md`、`operations/records/`、`operations/tests/`。
- Remote 初始化为仅在该服务器上的本地 Git 仓库，不默认配置 remote 或修改 Git 身份；主机等级默认 High。README 提供已核实用途、环境、导航、关键组件和验证/回退入口；画像注明来源、时间与未知项。整机盘点是独立任务，不是初始化或单服务诊断前置。
- 实际配置留在原生位置，资料只记录路径、用途、依赖、验证、漂移和历史，不复制为权威配置副本，不存敏感配置。导航或已登记画像受本次变更影响时，在获准范围内核实同步；历史整理到远端也须授权，不批量迁移。
- 多客户端接入时检查相关记录、Git 与实际状态，按路径和主题协作避让，不覆盖未解释改动，不引入服务级锁。提交锁仅保护 Git 提交，不保护系统变更或文档写入。

## 操作记录

- 规划前有索引就按对象、环境、组件和操作类型查相关记录，只读直接影响方案的详情。讨论和只读调查默认只在会话中记录；用户要求保存时，把位置和范围纳入授权。
- 变更方案包含留痕位置、主题文件范围与是否提交。已有授权覆盖时不重复确认；位置不可用时报告并明确替代方案，不擅自换持久化位置。
- 一条记录对应一个目标或独立变更边界。先找同目标未完成记录；调整方案、重试、调查和多轮验证更新原记录，不按命令、会话或尝试重复建记录。
- 首次实施前登记 `in-progress`；中断保留已做步骤与实际状态。完成后记录实际变更、验证、遗留问题和回退点，标记 `verified`、`failed`、`blocked` 或 `aborted`。不保存凭证或无助于决策的完整日志。
- 每次写入前复核路径在索引和工作树中的修改及主题归属，同一路径并发修改或归属不明时协调或暂停，不以旧内容覆盖新内容；其他路径已有暂存不阻塞本主题。

## 提交

- 验证及获准文档同步完成后，实施范围明确包含 commit 且项目规则允许时主动提交本主题。项目要求单独授权而未获得、只读任务、无 Git 或未验证时不自动提交，如实报告。初始化不自动包含提交，merge、push、deploy 分别授权；记忆、凭证和主题外文件不提交。
- 提交前列出精确主题路径，检查内容、staged/unstaged 差异、敏感信息与归属。共享文件混入其他主题时暂停；共用工作树不使用 `git add -A`、`git add .`、`git commit -a` 或无路径 commit。
- 在对应本机或已确认远端仓库的 Git common directory 原子创建 `ops-commit.lock`，记录主题、会话和开始时间，取得锁后才暂存/提交。占用时报告并暂缓，不抢占或自动清理疑似遗留锁，只释放本会话的锁。
- 持锁后重新核对 HEAD、工作区、索引及主题路径；同路径冲突、状态不明或期间修改时停止，不 reset、stash 或覆盖他人内容。锁不能阻止人工或不遵循协议的工具，因此提交前仍核对实际状态。
- 本主题新文件按精确路径 `git add -- <paths>`；本主题全部已知路径用 `git commit --only -m <message> -- <paths>`，提交指定工作区内容而非整个共享索引。不得 amend、跳过钩子或自动修改 Git 身份。
- 提交后核验文件列表、HEAD 和其他路径 staged/unstaged 状态。钩子、身份或并发检查失败保留现场并报告，不盲目重试；提交信息概括运维目标，不含敏感信息。
