# OpenCode 项目引入与更新

**已有项目先看 [更新记录](#更新记录)，再按 [后续更新](#后续更新) 审阅实际差异。首次使用看 [首次引入](#首次引入)；旧全局安装先看 [旧安装迁移](#旧安装迁移)。** 本文是唯一流程来源；`/onboard` 只负责定位并读取本文，不覆盖系统 `/init`。

## 首次引入

1. 克隆 dotbox，在任意目录运行克隆内的 `setup.sh`。脚本从自身位置解析克隆，只注册 `${XDG_CONFIG_HOME:-$HOME/.config}/opencode/commands/onboard.md`，正文指向本 README。不安装代理、技能、插件或其他配置，不启动 AI。
2. 在**目标仓库**打开 OpenCode，首次选用内置 **Build**，运行 `/onboard`。命令不指定 `agent` 或 `model`，以 `subagent: false` 保持当前会话；模板本身不含 shell 插值。克隆移动后重跑 setup；README 缺失时停止，不扫描其他克隆。已有同名个人命令不覆盖；项目命令或 JSON 定义可能遮蔽全局入口，遇到冲突先报告。
3. 按下面的调查、确认、生成和验收流程完成：保留 Build / Plan，只把 Coding 或 Ops 设为默认主代理。初始化属于当前工作区的项目元数据维护，不默认创建功能 Worktree、安装依赖、启动服务、部署或执行 Git 提交。

不带参数时，先检查现状：未引入则初始化；已有文件则核对默认代理和有效配置，按需补全，不重复覆盖；已完成则报告现状。`/onboard update` 按 [后续更新](#后续更新) 审阅差异。只使用这两种调用，其他需求在普通聊天中说明，不把外部文本或命令粘贴为参数：v2.0.32 原生命令会在参数展开后、模型收到请求前求值 shell 插值，提示词不能阻止该行为（[版本源码](https://github.com/anomalyco/opencode/blob/v2.0.32/packages/core/src/config/plugin/command.ts)）。

### dotbox 本身作为目标项目

不要仅因会话位于模板克隆就自动初始化；用户明确指定 dotbox 本身为目标时，可按相同流程引入 Coding。遵循根 `AGENTS.md` 的原地开发约定，完整生成本地 `.opencode/agents/coding.md`、`planner.md` 和 `.opencode/opencode.jsonc`；它们是项目自身配置，与 `opencode/` 下供其他项目审阅的源模板不同。

本仓库现有 `.gitignore` 忽略 `.opencode/`，生成文件仅在当前克隆使用，不进入公开配置归档，也不由 setup 同步。根 `AGENTS.md` 保留审阅和交接记录；换克隆时须重新核对实际文件，不能仅凭记录判断已引入。Build / Plan 保持可选，默认代理为 Coding。

### 调查与集中确认

执行引入的代理先检查 Git 状态、适用的祖先/根/子目录 `AGENTS.md`、README、清单与锁文件、CI、验证入口及主要架构。按需调查 `CLAUDE.md`、Cursor / Copilot 规则和已有 OpenCode 配置、代理、命令、技能与指令引用；保留局部适用范围和有效人工约定，不读取或展开凭证、私密引用。

从项目证据确定用途与现状后，一次集中展示重要决策及冲突，请用户确认：

- **Coding 或 Ops**：选择一个主模式；说明选用的流程、必要技能与拟修改文件。普通项目不额外强制 TDD 或多代理调查。
- **Coding** 默认保留源代理完整的 Worktree、计划、实施、验证、交付与受授权 Git 流程；仅由已确认的项目约定覆盖，例如原地开发，不把默认流程删成简短口号。
- **Ops** 从单文件代理引入授权、主机管理、调查、开发验证等操作协议，结合目标项目现有 runbook 适配。不依赖额外 Ops 技能，不要求访问模板作者的运维仓库，也不复制私有主机清单。
- 展示现有自定义主代理、全局遗留与所选模式的冲突。**不以选择默认代理为由禁用 Build / Plan 或用户其他主代理**；已有禁用项需核对来源，仅移除本次引入曾写入的 Build / Plan 禁用项，不覆盖更高优先级的管理策略。
- 模型继承用户现有选择，不硬编码 Provider 或模型；个人 MCP、凭证与无关配置不动。全局偏好源 [`AGENTS.md`](AGENTS.md) 仅作参考，不盲目复制到项目。

项目事实不足时标明未知，只就影响产出的缺口澄清；不猜测测试命令，不为形式创建空文档或技能。

### 生成自包含项目文件

确认后增量生成或合并以下内容，**不禁用 Build / Plan 或当前执行代理**：

| 文件 | 内容边界 |
| --- | --- |
| 项目 `AGENTS.md` | 项目事实、精确验证命令与前置条件、特殊边界、已有文档导航及简短引入记录；不复制通用代理流程 |
| `.opencode/agents/coding.md` **或** `ops.md` | 所选主模式完整流程与授权规则，适配项目实际路径 |
| `.opencode/agents/planner.md` | 按需只读规划子代理及主代理完整交接协议 |
| `.opencode/agents/reviewer.md` | 独立只读方案审查子代理，每轮检查边界、过度设计与语言 |
| `.opencode/skills/` | 仅必要专项方法及其被引用的支持文件、来源与许可 |
| 原有项目原生配置，或 `.opencode/opencode.jsonc` | 设置所选主模式的 `default_agent`，移除本次引入曾写入的 Build / Plan 禁用项；保留其他有效设置 |

生成文件必须自包含：不通过 `{file:...}`、软链接或运行时指令依赖 dotbox 克隆；内部引用改为项目内实际路径，技能支持文件一起引入。克隆仅用于以后审阅更新，不是日常工作前提。

先生成新代理、技能与规则，检查它们可用后，再合并 `"default_agent": "coding"`（Ops 则为 `ops`）。不写 `"build": { "disabled": true }` 或 `"plan": { "disabled": true }`，也不通过移动、删除或覆盖代理定义来替代禁用。

### 默认代理与验收

V2 会重新加载配置，且 `default_agent` 不会替换当前会话已经选择的代理。**保留 Build / Plan 可选**，不必在安装中切换代理来完成禁用，也不靠重启后台服务或等待固定秒数解决切换问题。

1. 验证生成文件、有效配置和代理列表：所选 Coding/Ops 是默认代理，Build / Plan 仍可选，Planner / Reviewer 已加载，Explore / General 未受影响。既有禁用来自其他来源、管理策略或用户自定义时报告冲突，不擅自覆盖。
2. 提醒用户当前会话可能继续使用先前选定的 Build/Plan；需要立即使用新代理时手动切换或新建会话。无需再次运行 `/onboard` 收尾。

选 Coding 时的最小配置如下；选 Ops 时将 `default_agent` 改为 `ops`：

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "default_agent": "coding"
}
```

此片段须与已生成的主代理配合，并按现有配置增量合并，不是覆盖整份配置的模板。Build / Plan 与其他已存在的用户代理保留；`planner`、`reviewer`、内置 `explore` 与 `general` 也保留。同名 Reviewer 已有自定义职责时先报告冲突，不直接覆盖。已确认归属的旧 `plan-designer` / `simplicity-reviewer` 如需迁移，应单独审阅，不因更换默认代理一并禁用。

v2 的 `agents.<id>.disabled: true` 会移除对应代理，不等于“不设为默认”。`default_agent` 只影响尚未选择代理的会话，**不会替换已有会话的选择**。权限规则追加且最后匹配生效，`skills` 数组跨来源累加；不能把“项目配置优先”解释成所有字段整块覆盖。OpenCode 内置技能依然存在，不宣称项目只剩所选技能。

### 流程与技能选择

- [Coding](agents/coding.md)：通用开发工作流；测试方法按任务需要选择，不把 TDD 作为额外初始化门槛。
- [Ops](agents/ops.md)：包含授权、连接与主机管理、调查、开发发布、工作区/Git、长任务及记忆协议，不再单独引入 Ops 技能。
- [Planner](agents/planner.md)：用户通过 `@planner`、明确自然语言要求调用，或同意主代理明确的调用建议时进入规划流程。可直接澄清需求，并在用户明确授权后读取必要的 `.env`、私钥等敏感文件，不输出敏感值。向主代理返回包含方案、复杂度和 AI 执行估期的 JSON；主代理向用户展示正常方案文本，不展示 JSON，不用人类编码工时替代 AI 估期。
- [Reviewer](agents/reviewer.md)：独立检查需求与范围、设计必要性、验证依据和语言表达，返回 JSON；不检查复杂度分级与 AI 估期，不管理轮次。主代理每轮新建审查会话，默认最多五轮，通过即结束；达到上限仍未通过时等待用户决定是否继续，未复审或代理不可用须如实说明，主代理自审不能代替。只讨论代理或普通“先想个方案”不触发该流程；规划与审查均不代替实施授权或行为验证，不自动切换回内置 Plan。
- **运维开发的规模约定**：设计前明确交付形态、使用范围和不承担的职责，重要分歧并入方案确认。具体规则见 [Ops](agents/ops.md#运维开发的规模约定)，不把验证要求变成额外功能清单。
- 开发领域按需选用 [响应式](skills/responsive-design/SKILL.md)、[无障碍](skills/accessibility-compliance/SKILL.md)、[API 设计](skills/api-design-principles/SKILL.md)、[PostgreSQL](skills/postgresql-table-design/SKILL.md)。保留 [第三方来源与许可](skills/THIRD_PARTY_NOTICES.md)。
- [agent-browser](skills/agent-browser/SKILL.md) 仅在浏览器自动化任务需要时选用，不默认安装浏览器工具或配置 MCP。

**代理承载流程，AGENTS 承载项目事实和特殊边界，skill 承载专项方法。** 避免将相同约束复制到多处。

### 验收与记录

检查生成文件的原生语法、真实引用、脱敏与最终 diff，核对有效配置来源、默认代理和 Build / Plan 可用性。旧全局代理/命令残留或配置来源冲突时报告实际结果，不以 JSON 写好就宣称行为已验证。中断后以现有文件和实际代理身份继续，不重建或覆盖人工修改。

静态检查只能证明文件和配置结构，不能证明模型会遵守授权、Planner 调用或 Worktree 流程。实际行为验收另按用户授权进行；初始化不默认执行真实 SSH、部署、提交、合并或推送，也不自动重启服务。

在项目 `AGENTS.md` 保留一条短记录，例如“dotbox：上次审阅 `<完整提交号>`；选用 Coding、Planner、Reviewer、API 设计；项目例外：原地开发；默认 Coding，Build / Plan 可选”。提交号由代理对命令定位的克隆执行 `git -C <克隆目录> rev-parse HEAD` 取得；有未提交差异时注明“另含未提交差异，尚无对应提交”，不虚构本轮 SHA。该记录表示审阅基线，不是运行时加载或当前代理身份的证明，不另建状态系统。

## 后续更新

在已初始化项目的所选主模式中运行 `/onboard update`。命令沿克隆路径读取本文更新记录，依据项目 AGENTS.md 的上次审阅提交与选用项审阅实际差异，说明哪些值得引入，确认后只更新相关项目文件。已有安装曾禁用 Build / Plan 时，在确认归属后恢复为可选；涉及更换或重命名当前代理时，先准备替代代理，切换后再移除旧代理。

由用户先将 dotbox 克隆更新到希望审阅的版本；不自动拉取或覆盖脏工作区。代理读取更新记录，并比较旧记录提交与当前实际版本中相关源文件的 Git 差异；旧提交不可取得、记录缺失或克隆有本地差异时说明限制，先建立可核对基线，不伪称完整增量审阅。

按项目已有定制选择性引入，保留未选用项和有效人工约定；重要行为、权限或模式变化集中确认。完成检查后更新 AGENTS 中的短记录即可，不建立额外状态系统、版本盖章器或自动同步任务。README 是导航和变更说明，不能替代实际 diff。

## 旧安装迁移

在原 dotbox 克隆运行：

```bash
bash uninstall.sh          # 仅预览
bash uninstall.sh --apply  # 交互确认后执行
```

卸载仅处理旧全局代理、技能、自定义命令、`opencode/AGENTS.md` 和自动更新任务：与旧安装基线一致的范围内文件、经核实的 dotbox 调度和必要元数据归档到临时目录，执行时输出位置；修改过、无基线或链接对象保留并报告，不触碰私有文件。**侧边栏整套文件、`cli.json`、`opencode.json`、旧 `config.json` 和 Kitty 配置不在卸载范围内，即使有旧基线也保留。** 不拆分插件，也不需要重新安装这些保留内容；如需完整移除它们，另行审阅并明确授权。执行模式停用核实的旧调度，不自动重启 OpenCode。预览不等于迁移执行，归档也不等于模型已停止加载旧内容。

`install.sh` 仅作无副作用、非零退出的退役提示。保留项需用户核对归属后另行处理；旧全局代理、技能、命令未清理前不能承诺项目隔离或所选默认代理生效。完成迁移后再运行 setup、按本文引入并新建会话核验。本次修改文档或脚本不代表已替用户执行迁移。

## 更新记录

### Planner 直接澄清与 Reviewer 职责划分

- Planner 可直接询问用户；`.env`、私钥等读取权限由禁止改为请求审批，正文要求用户明确授权读取范围与用途后才读取，不允许泄露敏感值或绕过更高层限制。Reviewer 的敏感文件限制保持不变。
- Reviewer 只审查当前方案，不检查实施复杂度分级、AI 估期或管理轮次；主代理按 Planner 流程管理默认五轮上限。
- 明确子代理以 JSON 向主代理交接，主代理向用户展示正常方案文本；同步公共规则中的 Planner 交互例外。源模板变更不自动同步本地或全局配置，也不代表已获得任何实际敏感文件的读取授权。

### Reviewer 按 Planner 风格精简

- Reviewer 改用短段落与编号规则，保留只读权限、独立审查及 JSON 结果，减少重复说明和固定输入清单。
- 审查以原始需求和最小必要设计为依据，建议本身不得引入过度设计；允许首轮通过，不为凑轮次找问题。复杂度与 AI 估期只核对合理性，不强制拆分耗时报表。
- 本次只调整 Reviewer 源模板及本文说明，不修改用户修订的 Planner，不自动同步项目或全局代理。静态检查不代表模型实际审查行为已验证。

### Ops 技能合并与正文精简

- 将 `ops-hosts`、`ops-investigation`、`ops-workflows` 及四份参考文件的必要原则合入 `agents/ops.md`，删除原文件。按授权、主机管理、调查、开发等主题组织，不再附完整操作教程。
- **授权策略调整**：保留 Local / Remote 及 Low / High 定义。Low 按已授权目标自主实施，High 写入前确认方案、影响与恢复办法。所有等级的只读连接、调查和验证均不额外确认。等级取用户指定或可信项目记录，未知时注明，不默认升为 High。
- 操作名称不自动改变主机等级。系统破坏、重要数据不可逆损失或管理连接失效等重大风险须说明并确认，已有批准覆盖时不重复问，不累计两次、三次审批。
- 凭证按用户授权使用，保留不泄露、不提交 Git 和不绕过工具权限的底线。移除固定 SSH 参数、认证后端、操作锁名及详细排错教学，交由模型按环境选择。原有权限配置不变，正文授权不覆盖工具限制。
- 放宽原有子代理数量和只读限定，改按并行收益与任务授权委派。Git 提交、合并、推送各自须获授权。项目已有更严格的保护约定仍须保留，不能以精简模板为由直接删除。
- Ops 只保留 Planner 入口。Planner 的交接流程改为引用 Ops 确认规则，不再另写一份 High 审批要求。已选 Ops 的项目同时审阅这处引用变化。
- 已选 Ops 的项目审阅新的完整代理，核对项目定制和引用后再移除本项目旧技能。不自动更新当前项目或全局配置，不直接删除其他项目或人工修改的文件。下方旧更新记录中的技能路径仅用于历史差异定位。
- 静态检查不代表真实 SSH、故障调查、删除或发布行为已验证。

### 运维开发规模确认与全流程保留

- Ops 在展开新增或明显改写自动化的设计前确认规模定位，而不只确认功能；沿用现有方案与交接字段，不新增规模档案或评分流程，不改变连接、High、删除和发布授权。
- Planner、Reviewer 同时接收原始需求、用户确认的规模约定、项目硬约束和代理候选设计；方案与压缩摘要保留规模约定，缺失时不能由当前架构倒推。审查先判断是否符合规模，再检查设计自洽性，不把实现需要当成用户需求。
- 防重、持久化、恢复和常驻组件须有实际依据；为新增机制继续加保障时先回查上游设计。超出规模须由用户决定，简化则从原始需求重建最小方案，不默认继承旧设施或让用户逐项裁剪技术清单。
- 开发与验证要求按实际输入和风险适用，不为检查项新增功能，不以缩减代码为由弱化必要安全和错误处理。已选 Ops 的项目共同审阅 Ops、Planner、Reviewer 及 `ops-workflows/references/development-verification.md`；源模板不自动同步到当前项目、其他项目或全局配置，静态检查不证明模型实际行为。

### Coding / Ops 各自精简措辞

- 分别精简 Coding 与 Ops 文件内部的重复措辞：Coding 压缩计划、实施和验收说明；Ops 合并确认交互说明、集中方案字段并缩短规模示例。不合并两种模式，不抽取公共层，不改变权限、确认次数、阶段性复查或既有例外；仅更新源模板，目标项目仍按更新流程审阅引入。

### Ops 按目的连续执行与简短确认

- 远程连接按可信本地等级区分：目标明确的 Low 可直接连接并完成请求范围内的只读调查，写入须有明确实施授权；High（含等级未知或不可信）即使只读也先取得连接授权，写入仍分别确认方案与执行。Low 上的高风险操作仍强制走 High，SSH 身份与信任核验不豁免。
- 单台及批量只读连接测试中，Low 项免额外连接确认，High 项集中确认；跳板按各自等级处理，不随终点降级。更新时共同审阅 `agents/ops.md` 与 `skills/ops-hosts/SKILL.md`，添加登记、删除及实时指纹采集的专项授权保持不变。

- Ops 先识别用户期望结果并确定完成标准，再连续调查、核验及完成获准处置；可执行的必要补证不留作“下一步”等用户催促，查因结果不冒充恢复完成。
- 单步写入或取证受阻时优先检查只读替代路径，继续其余独立工作；真正阻塞才说明缺口并请求必要决定，不扩大授权或无限调查。同步修正 `ops-investigation` 的收尾条件与示例。
- 必要批准、是/否与少量选项使用 OpenCode `question`；方案、命令和长说明留在正文，弹窗只放短问题与简短选项。不新增确认次数，不重复索取已有授权。
- 已选 Ops 的项目按更新流程共同审阅代理和调查技能；源模板不自动同步当前项目或全局运行配置。案例演练不替代真实会话中的工具调用与运维效果验证。

### Ops 深入调查与根因摘要

- 新增 `ops-investigation`：沿请求路径比较正常与异常，用支持证据、反证和最小取证收敛原因；区分已确认原因、较可信假设及尚未定位，不将相关性或重启恢复当作根因证明。
- 调查汇报先给结论，再给决定性证据、影响/恢复状态和必要下一步；按问题复杂度展开因果链，不输出排查流水账。保留应急缓解和原有授权边界，不新增调查代理或强制多代理循环。
- 已选 Ops 的项目可按更新流程共同审阅 Ops 入口及新技能，生成自包含项目文件。这里只更新源模板，不自动安装、同步到当前项目或全局配置；静态检查与合成案例演练不代表原生加载或真实故障调查已验证。

### Planner / Reviewer 拆分与自然语言调用

- Planner 只负责规划，新增 Reviewer 独立审查方案；取消同一代理按 `phase` 切换职责。支持明确自然语言调用及对明确调用建议的同意，保留 `@planner`；仅提及代理、普通规划请求或任务失败不自动启动。
- 方案形成后必须进入独立审查，每轮检查方案边界、过度设计和语言；单方案至少一次、最多五次审查调用，失败也计次，不因修订或重新设计重置。缺少有效审查不能以主代理自审冒充，达到上限仍未通过或修改后未复审须明确报告。
- 方案新增低 / 中 / 高复杂度及理由、AI 修改与验证的耗时区间和总估期，外部等待单列；证据不足时允许明确无法可靠估计，不编造承诺。表达减少套话和自造名词，保留行业术语。
- 已有项目按更新流程共同审阅 Coding/Ops、Planner 并引入 Reviewer，保留自定义职责与权限，检查同名冲突和实际加载。不只更新 Planner 而留下旧触发规则；源模板修改不自动同步当前项目或全局配置。静态检查不证明自然语言触发与五轮流程已实测。

### Ops 文件读取与传输授权

- 仅对敏感文件增加确认边界：明确授权读取或传输时不重复问；任务中才发现必须处理未获准的敏感文件时，先说明文件范围、源/目标与用途并取得同意。`.env` 只是例子，不以扩展名判断；普通文件沿用原有授权，不额外确认。Remote 连接和 High 的独立确认不变。
- 移除 Ops 对 `.env` 文件的无条件读取禁令（它只是先前误设限制的一例）；传输可能含敏感内容的文件时优先不展示内容，读取只取必要信息，凭证值不进入对话或日志；私钥等原有读取禁令保持。

### 保留 Build / Plan，按项目设置默认代理

- 新引入的 Coding/Ops 只设置 `default_agent`，不禁用 Build / Plan，也不因选择默认值禁用其他主代理；已有项目可在核对禁用项归属后移除本次引入的 Build / Plan 禁用项。
- 当前会话的代理选择不随默认值变化；想立即使用 Coding/Ops 可手动切换或新建会话，不再要求第二轮 `/onboard` 收尾。

### dotbox 自身使用 Coding

- 明确用户可指定模板仓库本身为目标项目，按既有原地开发约定准备 Coding / Planner，并设置 Coding 为默认代理。
- 项目 `.opencode/` 延续 Git 忽略约定；源模板与当前克隆本地使用的代理配置分别维护，记录不能替代实际文件和身份核验。

### /onboard 入口与安全交接

- setup 改为注册不绑定代理/模型的 `/onboard`；`/onboard update` 读取同一 README 更新流程，不再创建 `dotbox.md`。
- 重跑 setup 会移除与旧脚本生成内容完全一致的旧导航；修改过、其他克隆或链接对象保留并提示，不误删个人内容。
- 初始化先准备新代理并保持 Build / Plan 可用；不再执行禁用收尾。更新涉及替换当前代理时仍须先准备替代代理。

### 卸载范围修正

- 仅退出旧全局规则与自动更新，不再归档 UI、侧边栏或通用配置，避免插件部分文件被修改时发生拆分。
- 使用旧版卸载脚本但尚未执行的用户，更新脚本后重新预览；若已经归档插件文件，先核对归档和当前修改，再在确认后恢复缺失文件，不覆盖现有定制。setup 不会自动补装插件。

### 项目化引入（本轮，提交号以实际 Git 记录为准）

- 全局安装与定时同步退役；setup 原先只写 README 导航，现由上面的 `/onboard` 入口替代；uninstall 提供有基线的保守迁移。
- 删除自定义 init；首次由 Build 调查与集中确认，再生成自包含的 Coding 或 Ops 项目配置。
- 旧版流程曾禁用 Build / Plan 与未选 dotbox 主模式；现以所选 Coding/Ops 为默认、Build / Plan 可选，其他用户代理不因选择默认值而禁用。
- 取消额外强制 TDD / 多代理初始化；明确流程、项目事实和专项方法分层。
- 精简 Coding/Ops 的重复规则；Code 仍默认完整 Worktree，Ops 的授权集中在主代理，技能只提供方法。新增隔离开发验证参考，不把项目主机、路径或 live 架构选择推广为全局规则。
- 移除代理固定模型和安装盖章，主代理保留独立的凭证、授权与证据底线，不依赖另装全局规则。
- 后续按项目 AGENTS 的短记录审阅 README 和真实差异，选择性更新，不自动同步。
