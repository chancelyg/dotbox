分析当前仓库并创建或更新根目录 `AGENTS.md`。

目标是建立项目级长期上下文，而不是重复 Coding Agent 的通用开发流程。

## AGENTS.md 应包含

* 产品定位、核心目标和主要业务流程；
* 项目架构、主要目录和模块职责；
* 必须保持的业务、数据、安全和兼容性边界；
* 当前项目特有的技术约束和实现原则；
* 项目真实使用的 format、lint、typecheck、test、build 等验证入口；
* `docs/` 下详细设计文档的必要导航。

## 文档分层

`AGENTS.md` 只保留长期、高频、全局的信息。

复杂或低频设计统一维护在 `docs/`，例如：

* 产品详细设计；
* 架构设计；
* 模块设计；
* API 和数据模型；
* 状态机；
* 外部服务集成；
* 技术决策；
* 迁移方案。

需要时在 `AGENTS.md` 中增加简短索引，例如：

```markdown
## 项目文档

- `docs/product.md`：产品与业务流程
- `docs/architecture.md`：系统架构和模块边界
- `docs/scoring.md`：评分逻辑

处理对应领域时按需读取相关文档。
```

不要为了形式创建空文档。

## 不应写入 AGENTS.md

以下通用流程由 `coding` agent 统一负责，不在项目中重复：

* Worktree 开发流程；
* 功能分支管理；
* commit / merge / push 流程；
* 验收和清理流程；
* 通用安全规则；
* 通用开发步骤和汇报格式。

只有当前项目确实需要覆盖默认开发流程时，才在 `AGENTS.md` 写明特例。

## 执行原则

修改前检查现有：

* `AGENTS.md`；
* README；
* `docs/`；
* 项目结构；
* 依赖和构建配置；
* 测试和 CI 配置。

优先从实际代码和配置得出结论，不根据技术栈模板臆测。

已有 `AGENTS.md` 时以增量维护为主，保留仍然有效的人工约定。

`/init` 属于项目元数据维护任务：

* 直接在当前工作区执行；
* 不创建功能 Worktree；
* 不自动 commit、push 或 merge。

完成后检查：

* 内容是否准确反映当前项目；
* 是否包含未经项目证据支持的推测；
* 是否错误混入通用 Coding 工作流；
* `docs/` 引用是否真实存在。
